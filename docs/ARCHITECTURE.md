# 架构约定：二维玩法与三维表现（2.5D）

> **状态：Issue #3–#7 已包含固定步进、玩家移动、JSON 关卡、敌阵运动及玩家射击/二维扫掠碰撞/计分。敌人攻击和终局规则尚未实现。** 规则核心在 `src/core/`，场景在 `src/render/`；进度见 [P1 路线图](ROADMAP.md)。

## 目标及不可变边界

基于 React + TypeScript + Three.js + Vite，在 `/React-SpaceInvader/` 下运行纯静态《太空侵略者》。这是经典二维射击游戏的三维可视化，而不是三维飞行射击：
- 游戏规则使用唯一二维平面 `(x,y)`：x 横向、y 纵向；玩家沿固定 y 仅改变 x；敌人及所有子弹的**逻辑**位置/速度/碰撞都只采用二维坐标。
- Three.js 可将该平面映射至 `z=0`，各模型延伸出的 z 厚度、粒子深度及透视只供视觉表现。不要给飞船、敌机、子弹增加可控制或可导致碰撞变化的 z 坐标。
- 正常交战的相机以**稳定的正面可读视角**展示战场，不因戏剧运镜导致误判碰撞。开局、过关、结算期间可做平移、旋转、缩放；演出不得改变二维运动/命中结果。
- 不引入三维物理引擎；采用独立可测试的二维碰撞（必要时扫掠碰撞解决高速子弹穿透）。规则时钟建议固定 60Hz，Three.js 帧率可独立变化；仅在渲染层插值。

## 模块及数据流

| 规划目录 | 单一职责 |
| --- | --- |
| `src/core/` | 不依赖 React/DOM/Three.js 的状态、合法命令、固定步进、二维运动/碰撞、计分、生命、胜负、可复现随机事件 |
| `src/levels/` | 关卡 JSON 的带版本号解析、严格校验、加载以及规范化数据 |
| `public/levels/` | 带版本号的 JSON 关卡及清单，可只改数据并重新构建部署 |
| `src/render/` | Three.js 的立体场景、相机、光影、特效、资源回收、二维到三维显示映射 |
| `src/input/` | 键盘（左右/A/D/空格）等输入映射为合法逻辑命令；失焦和暂停释放输入 |
| `src/ui/` | React 的简体中文菜单、分数/生命显示、暂停、胜负界面 |
| `tests/` | 无界面逻辑、固定种子确定性、数据校验、真实浏览器及 Pages 子路径验证 |

当前实际的数据流：`输入 → 合法命令 → 纯逻辑引擎（固定步长）→ 游戏状态和结构化事件 → Three.js 场景 / React UI`。渲染器和组件不得倒写逻辑状态，也不允许三维模型位置成为规则真值。目录随 Issue 实施创建，不预置无用空文件。Issue #3 的固定时钟、种子随机数、命令状态机和二维边界工具已落地；Issue #4 增加了玩家二维位置、固定速度/尺寸及合法方向命令；键盘在 `src/input/` 只负责按键映射与失焦/暂停释放，Three.js 飞船模型仅同步快照位置，尚无射击碰撞。

## 关卡格式（P1/3 正式落地）

数据为纯 JSON，不允许可执行代码。目标基础字段：
- `schemaVersion`：数据契约版本；`id`、`metadata`：标识、玩家可见名称、描述。
- `world`：战场宽高、边界/失败防线及必要的玩家起点。
- `waves`：多个有时序的波次；敌机类型、编队（行列/间距或明确坐标）、生成时刻/条件、运动与射击节奏。
- `difficulty`：允许的数据化速度/射击频率等难度参数，避免仅靠硬编码。
- `victory`：当所有应生成波次和存活敌人完成时的胜利判定等，可验证的有限配置。

上述职责已由 #5 在 `src/levels/parse.ts` 的 v1 严格校验器及 `src/core/level.ts` 的不可变纯 TS 类型中落地：编队是 `type/rows/columns/startX/startY/spacingX/spacingY`，每波还有 `spawnAtSeconds`、`movement.horizontalSpeed/descentPerTurn`、`attack.shotsPerMinute/projectileSpeed`；难度为 `speedMultiplier/fireRateMultiplier`。版本仅接受 1，未来版本需显式迁移。严格拒绝不支持版本、缺失字段、NaN/越界参数、未知敌机类型、无效时序、错误资源引用和超出限制的数据。错误须具备可诊断的简体中文提示，不能悄悄退回硬编码关卡。

Issue #5 已证实仅修改 `public/levels/first-contact.json` 的 `formation` 可改变静态编队数量、位置和类型；运动/射击/多波次的配置字段先校验和保留，不在 #5 执行，分别留给后续 Issue。解析失败时展示中文错误，不注入默认敌阵；加载使用 Vite `BASE_URL`。

## 游戏画面的减法原则（2026-10-17 确认）

- 默认页面是沉浸式战场，而不是仪表板、技术演示 PPT 或多层卡片。Three.js canvas 铺满可用视口；逻辑世界采用适合桌面横屏的宽高比，并通过正交相机缩放适配窗口，保留完整规则坐标。
- 只保留弱化的空间底色和必要边界；**网格、坐标、固定更新频率、随机种子、步进等只在主动打开调试模式后显示**。正式 HUD 以分数/生命/关卡/暂停为上限，不加入解释性技术文字。
- 视觉减法不能削弱功能：React 状态机、固定 60Hz 规则、三维世界映射与无界面测试继续保持；桌面/移动端保证游戏画布为视口主体。用户反馈布局、配色、视觉问题时应直接改代码而非重复讨论设计方案。

## #6 编队运动

`src/core/formation.ts` 由二维敌机包围盒计算下一次位移，水平到边缘就反射剩余路程、整体下压；高速及长间隔也不穿过边界。仅 `GameEngine.stepTicks` 推进逻辑；`Three.js` 每帧从快照同步坐标，不参与判定。关卡每波 `movement` v1 要求 `horizontalSpeed`、`descentPerTurn`、`startDirection`、`moveEveryTicks`；当前只执行第一波。最低边界处停止进一步下压，生命/失败判定留给 #8。

## #7 玩家射击、事件与计分

纯 TypeScript `src/core/combat.ts` 实现**运动目标相对坐标扫掠 AABB**（同时计算弹道 y 位移与敌阵 x/y 变化），不依赖 Three.js 模型/碰撞。`GameEngine` 接受 `FIRE`（立即请求）及 `SET_FIRING(active)`（空格长按），只在运行态有效；每 12 tick 最多一发，使用 60Hz 固定步进；玩家弹道 x 固定、y 向上，超出战场清理。先命中的目标被一次性销毁，按 scout=10/raider=20/guardian=30 加分，发布 `enemy-hit` 事件，禁止同目标重复计分。Three.js 只据快照画弹体及消费事件生成短暂光效；React 只显示极简分数 HUD。重置清空射弹、计分、冷却与输入状态；暂停停止射弹与敌阵。敌方伤害和胜负（#8）不在本轮。
