# 体系结构与数据驱动关卡约定（规划）

## 目标边界

单页静态站点（React + TypeScript + Three.js + Vite），通过 GitHub Pages 的 `/React-SpaceInvader/` 子路径部署。当前仅测试 WebGL 能被 React 正确初始化；**本文定义目标结构，不表示对应模块已经实现。**

## 模块职责（后续逐步建立）

| 模块 | 职责 |
| --- | --- |
| `src/core/` | 纯逻辑游戏状态、时钟、命令、碰撞、计分、胜负判断；不得依赖 DOM、React、Three.js |
| `src/levels/` | 关卡数据结构、版本迁移、解析校验、加载接口 |
| `public/levels/` | 可独立替换的 JSON 关卡和清单，按需加载 |
| `src/render/` | Three.js 场景、相机、特效与资源释放；只呈现状态 |
| `src/ui/` | React 菜单、提示、暂停、界面状态 |
| `src/input/` | 键鼠/触控输入映射为纯逻辑命令 |
| `tests/` | 规则、数据校验、确定性回归以及浏览器渲染检查 |

目录随对应 Issue 创建，**不提前引入空壳实现**。

## 关卡数据契约

关卡应为 **JSON 数据而非可执行代码**。正式实现前必须确定 `schemaVersion`、`id`、`metadata`、`world`、`waves`、`difficulty`、`victory` 等字段的精确定义，并提供结构验证与无界面测试。

设计原则：

1. 波次、生成时间、敌机类型/编队、速度、攻击参数与胜负条件从数据读取，不能写死在 React 或 Three.js 内。
2. 加载时检查版本、数值范围、引用存在性及无效资源；错误时展示清晰诊断而不是悄悄退化。
3. 随机编队与掉落使用可复现种子；允许不启动浏览器的无界面测试。
4. 关卡逻辑与三维表现解耦，避免只有视觉动画却没有可检验的游戏规则。
5. 资源路径统一使用 Vite 的 `BASE_URL` 或经审核的相对路径，生产项目页不能错误地从域名根目录载入资源。
6. 预留多关卡切换与关卡版本兼容；数据文件不内嵌脚本。

目前**不创建示例关卡**，避免把未经实现和验证的配置误认为可玩的内容。

## 发布与验收

- PR：`npm run verify`；仅检查类型、生产构建和静态资源。
- 合并 `dev`：相同验证后上传 Pages artifact 并通过官方 `deploy-pages` 发布。
- 每个游戏功能 Issue 以后另增必要的纯逻辑测试与浏览器测试，不用空页面通过 CI 冒充玩法实现。
- 上线后人工或浏览器自动化访问项目页，确认实际 WebGL 渲染、脚本加载、控制台错误和移动端表现；只见到 Actions 绿色不等于视觉验收。
