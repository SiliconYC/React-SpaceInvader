# 架构约定：二维玩法与三维表现（2.5D）

> **状态：P1 Issue #3–#9 已实现二维固定步进、玩家/敌机动作、双方射击、扫掠碰撞、计分生命、双关卡选择及多波次通关，所有规则与 Three.js 解耦。** 规则核心在 `src/core/`，场景在 `src/render/`；进度见 [P1 路线图](ROADMAP.md)。

## 目标及不可变边界

基于 React + TypeScript + Three.js + Vite，在 `/React-SpaceInvader/` 下运行纯静态《太空侵略者》。这是经典二维射击游戏的三维可视化，而不是三维飞行射击：
- 游戏规则使用唯一二维平面 `(x,y)`：x 横向、y 纵向；玩家沿固定 y 仅改变 x；敌人及所有子弹的**逻辑**位置/速度/碰撞都只采用二维坐标。
- Three.js 可将该平面映射至 `z=0`，各模型延伸出的 z 厚度、粒子深度及透视只供视觉表现。不要给飞船、敌机、子弹增加可控制或可导致碰撞变化的 z 坐标。
- 正常交战的相机以**稳定的正面可读视角**展示战场，不因戏剧运镜导致误判碰撞。开局、过关、结算期间可做平移、旋转、缩放；演出不得改变二维运动/命中结果。
- 不引入三维物理引擎；采用独立可测试的二维碰撞（必要时扫掠碰撞解决高速子弹穿透）。规则时钟建议固定 60Hz，Three.js 帧率可独立变化；仅在渲染层插值。

## 模块及数据流

| 规划目录 | 单一职责 |
| --- | --- |
| `src/core/` | 不依赖 React/DOM/Three.js 的状态、合法命令、固定步进、二维运动/碰撞、计分、生命、胜负、可复现随机事件 |
| `src/levels/` | 关卡 JSON 的带版本号解析、严格校验、加载以及规范化数据 |
| `public/levels/` | 带版本号的 JSON 关卡及清单，可只改数据并重新构建部署 |
| `src/render/` | Three.js 的立体场景、相机、光影、特效、资源回收、二维到三维显示映射 |
| `src/input/` | 键盘（左右/A/D/空格）等输入映射为合法逻辑命令；失焦和暂停释放输入 |
| `src/ui/` | React 的简体中文菜单、分数/生命显示、暂停、胜负界面 |
| `tests/` | 无界面逻辑、固定种子确定性、数据校验、真实浏览器及 Pages 子路径验证 |

当前实际的数据流：`输入 → 合法命令 → 纯逻辑引擎（固定步长）→ 游戏状态和结构化事件 → Three.js 场景 / React UI`。渲染器和组件不得倒写逻辑状态，也不允许三维模型位置成为规则真值。目录随 Issue 实施创建，不预置无用空文件。Issue #3 的固定时钟、种子随机数、命令状态机和二维边界工具已落地；Issue #4 增加了玩家二维位置、固定速度/尺寸及合法方向命令；键盘在 `src/input/` 只负责按键映射与失焦/暂停释放，Three.js 飞船模型仅同步快照位置，尚无射击碰撞。

## 关卡格式（P1/3 正式落地）

数据为纯 JSON，不允许可执行代码。目标基础字段：
- `schemaVersion`：数据契约版本；`id`、`metadata`：标识、玩家可见名称、描述。
- `world`：战场宽高、边界/失败防线及必要的玩家起点。
- `waves`：多个有时序的波次；敌机类型、编队（行列/间距或明确坐标）、生成时刻/条件、运动与射击节奏。
- `difficulty`：允许的数据化速度/射击频率等难度参数，避免仅靠硬编码。
- `victory`：当所有应生成波次和存活敌人完成时的胜利判定等，可验证的有限配置。

上述职责已由 #5 在 `src/levels/parse.ts` 的 v1 严格校验器及 `src/core/level.ts` 的不可变纯 TS 类型中落地：编队是 `type/rows/columns/startX/startY/spacingX/spacingY`，每波还有 `spawnAtSeconds`、`movement.horizontalSpeed/descentPerTurn`、`attack.shotsPerMinute/projectileSpeed`；难度为 `speedMultiplier/fireRateMultiplier`。版本仅接受 1，未来版本需显式迁移。严格拒绝不支持版本、缺失字段、NaN/越界参数、未知敌机类型、无效时序、错误资源引用和超出限制的数据。错误须具备可诊断的简体中文提示，不能悄悄退回硬编码关卡。

Issue #5 已证实仅修改 `public/levels/first-contact.json` 的 `formation` 可改变静态编队数量、位置和类型；运动/射击/多波次的配置字段先校验和保留，不在 #5 执行，分别留给后续 Issue。解析失败时展示中文错误，不注入默认敌阵；加载使用 Vite `BASE_URL`。

## 游戏画面的减法原则（2026-10-17 确认）

- 默认页面是沉浸式战场，而不是仪表板、技术演示 PPT 或多层卡片。Three.js canvas 铺满可用视口；逻辑世界采用适合桌面横屏的宽高比，并通过正交相机缩放适配窗口，保留完整规则坐标。
- 只保留弱化的空间底色和必要边界；**网格、坐标、固定更新频率、随机种子、步进等只在主动打开调试模式后显示**。正式 HUD 以分数/生命/关卡/暂停为上限，不加入解释性技术文字。
- 视觉减法不能削弱功能：React 状态机、固定 60Hz 规则、三维世界映射与无界面测试继续保持；桌面/移动端保证游戏画布为视口主体。用户反馈布局、配色、视觉问题时应直接改代码而非重复讨论设计方案。

## #6 编队运动

`src/core/formation.ts` 由二维敌机包围盒计算下一次位移，水平到边缘就反射剩余路程、整体下压；高速及长间隔也不穿过边界。仅 `GameEngine.stepTicks` 推进逻辑；`Three.js` 每帧从快照同步坐标，不参与判定。关卡每波 `movement` v1 要求 `horizontalSpeed`、`descentPerTurn`、`startDirection`、`moveEveryTicks`；当前只执行第一波。最低边界处停止进一步下压，生命/失败判定留给 #8。

## #7 玩家射击、事件与计分

纯 TypeScript `src/core/combat.ts` 实现**运动目标相对坐标扫掠 AABB**（同时计算弹道 y 位移与敌阵 x/y 变化），不依赖 Three.js 模型/碰撞。`GameEngine` 接受 `FIRE`（立即请求）及 `SET_FIRING(active)`（空格长按），只在运行态有效；每 12 tick 最多一发，使用 60Hz 固定步进；玩家弹道 x 固定、y 向上，超出战场清理。先命中的目标被一次性销毁，按 scout=10/raider=20/guardian=30 加分，发布 `enemy-hit` 事件，禁止同目标重复计分。Three.js 只据快照画弹体及消费事件生成短暂光效；React 只显示极简分数 HUD。重置清空射弹、计分、冷却与输入状态；暂停停止射弹与敌阵。敌方伤害和胜负（#8）不在本轮。

## #8 敌弹、生命与终局闭环

`GameEngine` 固定时间步按 `3600 / (shotsPerMinute × fireRateMultiplier)` 计算敌弹间隔（四舍五入至少 1 tick）。可发射者来自**当前存活敌机各列最底部的单位**，统一种子 PRNG 选择，发射事件与命中事件结构化输出。敌弹按 JSON 速度沿 y 向下，使用 `sweptHitTime` 对上一/当前玩家位置判定碰撞，击中弹删除、扣 1 生命，60 tick 无敌窗防止连续伤害，同一弹不可重复伤害。玩家 3 生命归零或任意敌机底部触及 `playerY + PLAYER_HEIGHT/2 + 0.5` 防线即失败；**敌机清空且不存在待生成波次**则胜利。终局 `won/lost` 不接受移动/发射/暂停/继续，`RESET` 全面复原生命、弹体、关卡首波、种子、分数、时钟、终局状态，且可以再次 `START`。保留旧 `ended` 调试结束指令。React 仅显示状态，Three.js 只消费快照/事件；双关卡/后续波次执行仍由 #9 实施，不能提前自动胜利。

## #9 双关卡清单与波次调度

`public/levels/index.json` 是版本化列表（ID、简体中文名称/简介），`src/levels/catalog.ts` 以严格模式校验唯一、受限的同源文件名，不接受额外字段和路径跳转；`loadLevel` 对目标文件进行 v1 解析，并核实内部 ID 与请求名称一致。至少包含 `first-contact.json`（一波）和 `crossfire.json`（两波、不同机型、速度/火力/难度）。选项以 JSON 清单驱动，React 不硬编码第二关名称或阵列；加载成功才替换旧引擎/渲染会话，无效文件保留旧状态并显示中文错误。

引擎中的 `currentWaveIndex`、`pendingWaves` 与 `waveStartedAtTick` 只接受 `LevelPlan.waves` 数据。必须上一波被击落清空且逻辑 `tick >= ceil(spawnAtSeconds × 60)` 后才能生成下一波；若前一波较晚清空，则立即进入符合时序的后续波。波次更替保留分数/生命/种子连续性，清理跨波射弹，重新绑定本波移动、射速和方向，并发送结构化 `wave-started` 事件。等待期间继续计时、可暂停、未完成全部波次绝不提前胜利。最终波全灭才触发胜利；重置回到第一波及初始种子。版本升级必须单独提供迁移器及新测试，不能静默接受未知字段。

## P2 #21 模型与资源基线

`src/render/ShipModels.ts` 一次性创建玩家机、轻型 scout、双舱 raider、装甲 guardian 四种结构不同的原创 3D 模型原型。通过 `Group.clone(true)` 实例化敌机，所有同型号实例 **共享 BufferGeometry/Material**，不在每次出现/每帧分别分配，死亡从 scene 移除；切关调用 renderer.dispose 统一释放会话级纹理/几何/材质。程序生成稀疏低亮尘点和补光；正交相机保证 `(x,y)` 瞄准、边界与此前完全一致，三维轮廓绝不参与碰撞。模型截图与 GPU 资产计数由 `tests/models.browser.spec.ts` 捕获；逻辑玩法没有修改。

## P2 #22 轻量战斗视觉反馈

`src/render/CombatFX.ts` 只消费 `GameEvent` 和只读快照：开火小闪、敌机击毁碎片、玩家受击闪光、波次启动短促低强度环形脉冲、胜败淡化光圈；不增音乐、不产生任何命中规则。每次效果由完整事件标识去重（最多记录最近 512 条），全局同时活动实例上限 72，所有粒子共享预先分配的两套几何和五种材质，没有音视频定时器、渲染器外 RAF 或每帧新建 GPU 资产。视觉寿命最高 800ms；暂停和重置清空特效，切关/卸载自动 `dispose()`。降低动态效果选项 `prefers-reduced-motion` 限制粒子。仅波次切换时正交相机最多 1.2%/550ms 的轻脉冲，战斗过程保持完全静止。浏览器实拍快照及数据属性（fx active/emitted/kind/gpu assets）对生命周期进行回归；逻辑 seed/tick/collision/score 完全由原 `GameEngine` 维护。

## P2 #23 行为差异和可重复难度回归

`WavePlan.behavior` 以 v1 **可选** JSON 字段支持 `armorHits` 和 `volleySize`（各 1～3 整数，省略默认 1/1），不破坏存量配置，未来不兼容更新应另开 schemaVersion 并显式迁移。规则层 `EnemyState.hp/maxHp` 保留唯一敌机 ID，第一次装甲命中触发 `enemy-damaged`，只在耐久归零时 `enemy-hit` 加一次分。齐射只从不同存活的底部敌机列发射，按单个随机索引+确定性间隔选择位置，不改变二维物理和游戏种子。FX 为伤害显示 amber 小环，不决定耐久。
`scripts/measure-difficulty.mjs` 在 CI `verify` 中比较 P1 初始 JSON 数值与当前 v1 更新：6 个指定种子、同一个追踪射击自动玩家、固定 60Hz、最长 70s，输出玩家/敌方发射数、受伤、击毁、装甲受损、得分、终局和耗时。机器人并不等同真人；自然实玩需要后续人工观察。两关全部字段仍受严格 parser 与 Chromium 回归保护。

## P2 #24 原创音频与隐私

Web Audio `src/audio/GameAudio.ts` 实时合成七种短促原创波形音效（玩家发射、敌机击毁、装甲受击、玩家中弹、下一波、胜利、失败），以及音量极低的双声部持续氛围声；没有外部音频、版权采样、运行时联网或 CDN。引擎 `GameEvent` 唯一映射、去重最近 384 个事件，最多 12 条短音效同时播放；音轨只生成 2 个长寿命振荡器。资源随会话和组件卸载停止、断开并关闭 AudioContext。

**只有用户点击开始或恢复时创建/恢复音频上下文**；设置面板的勾选不会触发播放。浏览器禁用自动播放或无 Web Audio 时安静降级，`localStorage` 拒绝/损坏时回到预设（音效和音乐开启，主音量 32%）。首次开始前绝不自动播放；暂停、失焦、切关、重置或结束停止氛围声；胜负终局仍允许一声结算提示。偏好仅储存在本机，不上传。

自动测试覆盖浏览器首次解锁、不同开关、刷新存储、拒绝存储和禁用音频，且不触及核心规则。**当前验收使用浏览器音频接口和程序计数，无法通过远程环境人工听感，主观听感验收待人耳确认。**

## P2 #25 本地排行榜

`src/scores/localScores.ts` 使用格式 `{version:1,entries:[]}` 的本机 `localStorage`，仅写入 `game-finished`（真实 win/lost）事件对应的完成局成绩；重置或页面未完成不写。记录关卡、结果、最终分数、完成波次数、总波次、固定 60Hz 逻辑 tick、随机种子和 ISO 时间。每个会话使用随机 ID 防止重复 React 渲染导致重记；全局固定相同种子允许玩家主动重新完整游玩，不误判为同一局。分关卡最多保留八个成绩，按积分降序、同分先胜利、再按逻辑时长/日期/ID 排。显示非战斗态简洁成绩面板、结算页个人最好成绩；清除全部关卡成绩要求浏览器二次确认。版本不兼容、异常积分/日期、损坏 JSON 或 Storage 禁止访问时安全丢弃无效数据，游戏继续运行；不发送任何资料到服务器，也无反作弊、跨设备排行或账号功能。

## P2 #26 触屏输入、GPU 与浏览器生命周期

`src/input/TouchControls.ts` 用 pointerId 同时跟踪左右移动和射击，两方向抵消，同样只调用 `SET_MOVEMENT/SET_FIRING`；取消/离开捕获、页面失焦、后台、暂停、卸载均释放按键。触屏操作浮在画面底部，安全区内；桌面键盘不变。透视规则仍正交镜头、仅按显示视口调整裁切范围：触屏底部预留少量视觉空间，二维位置、玩家瞄准及物理世界完全不变。

低端移动设备通过 `matchMedia('(pointer:coarse)')` 将 WebGL 分辨率倍率由原上限 2 限制为 1.5；其他设备保留 2。每帧只读取 `renderer.info` 已有 draw calls、GPU geometry/texture 数量，浏览器性能测试记录实际软件 Chromium SwiftShader 的帧间隔，验收上限约束活动绘制、几何与粒子数，`docs/P2_BASELINE.md` 已识别的独立敌机网格分配由 #21 修复，#22 限制最多 72 粒子。数据仅来自 CI 实际记录，非真实手机硬件 GPU 跑分。WebGL 上下文丢失时停运游戏时钟、不渲染并显示等待恢复提示；还原后复用一个 RAF 和 WebGL 会话，避免隐藏时间补帧；原生失焦和触控释放同样生效。测试包括 Chromium 移动设备触控模拟、横竖屏截图、多指按住/松开、连续切关内存增长上界、帧率统计以及支持时的真实上下文丢失/恢复。真人手机兼容性及人体工学体验仍需设备手测。
