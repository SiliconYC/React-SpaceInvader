# P3 场景图层与近景遮挡契约（#36）

- `starfield`、`celestial`、`environment`：仅视觉层；位置/旋转独立于二维规则，所有实体须在战斗投影后方。
- `combat`：玩家、三种敌机、双方子弹、网格调试和战斗粒子，来自 `GameSnapshot` 的 XY 逻辑状态。任何装饰不得改变其深度测试、命中盒或逻辑状态。
- `foreground`：仅在边角可见，必须经 `CombatSceneLayers.addForeground` 进行登记，提供**真实屏幕投影外接矩形**的动态回调；未登记的物体不允许直接加到此组。回调抛异常、坐标无效、竖屏或投影侵入战场、顶部 HUD、底部操作区时一律隐藏。
- 最前 HUD：既有 DOM/CSS 层，不放进 WebGL 世界，也不通过 Three.js 获取点击事件。

前景安全层采用**先于战斗对象绘制、不写深度、不参与透明排序**的防遮挡渲染契约。大小、滚动和镜头改变后都要重新估算屏幕外接矩形；不得凭世界 z 坐标猜测不会遮挡。若外接矩形穿入安全区，宁可不画。当前 A 组不创建实际近景模型，后续 #45 必须通过此接口接入并在移动时计算边界。

弱透视与正交对照通过 `?projection=ortho` 切换，纯二维投影见 `src/render/CombatProjection.ts`。同一逻辑 z=0 平面的中心点投影与宽屏、横屏、竖屏自适应投影保持一致。触屏安全区域以及浏览器照片实测分别由 `tests/scene-layers*.ts` 和 `tests/projection.browser.spec.ts` 覆盖。

**本次没有制造土星、岩石或背景大图。** 它们分别由 C 组制作；不得把未来资产或 WebGL 效果视为已经落地。
