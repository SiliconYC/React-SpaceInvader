# P4 C 组：动作导演与战斗特效验收记录

> 状态：**开发与自动化验收**。用户批准继续制作 C1–C3，**尚未认可商业级美术**。#69、#71 不关闭；后续正式镜头导演属于 #83。

## 源码与规则隔离

| 模块 | P3 基线 | P4 C 组 |
|---|---|---|
| 玩家 | 基于墙上时间的三角姿态 + 正弦悬停 | 固定引擎 tick 的 hover/launch/cruise/brake/reverse 导演，快速换向与受限惯性；双喷口随视觉推力变化 |
| 敌机 | 仅 kind + ID 相位正弦波 | 共同编队节奏 + 固定 ID 局部相位 + 规则折返／开火／装甲受击脉冲，Scout／Raider／Guardian 差异化 |
| 命中 FX | 72 个独立 Mesh 上限，最多与活动粒子数同比增加绘制调用 | 8 个常量 InstancedMesh 批次，合计最多 72 个活动视觉粒子；原生三维低模碎片、甲壳环、发射火花、胜败不同收束 |
| 子弹 | 双方共享胶囊体，每颗创建新 Mesh | 玩家短尾光矛和敌方下行铜色尖弹，复用共享几何与闲置 Mesh |
| 相机 | 波次 FX 曾改变相机 zoom | C 组保持战斗相机稳定，不新建镜头导演或随机屏幕抖动 |

玩家 XY 根节点、射击位置、碰撞盒、命中判定、规则速度、随机种子完全留在 `src/core/`；粒子不存在于规则快照中。动作只通过已有 `GameSnapshot.tick`、`formationTurns`、`GameEvent` 驱动；短暂 FX 只读既有 `performance.now()` 为事件局部生命周期，不增加游戏时钟／循环。减少动态效果会压低活动特效数量且停用机身姿态。暂停清理特效，波次/重置不会遗留旧事件。

## 可执行真实浏览器证据

- `tests/p4-c1-motion.browser.spec.ts`：1920×1080 起飞／急停／反向／射击、暂停定格、手机横竖屏，视频与资源数据。
- `tests/p4-c2-motion.browser.spec.ts`：三类单位实时编队录屏、每类实例绘制调用、暂停定格、移动端实况。
- `tests/p4-c3-fx.browser.spec.ts`：Guardian 多段护甲、击毁、胜利、密集事件（15+）、受限资源、复位／减少动态效果、横竖屏。
- `tests/combat-fx.test.ts`：28 次击毁后仍最多 72 粒子、8 批，重复事件不重复播放、暂停与复位重用。
- CI 与 Pages 发布工作流各自在 **真实 Chromium + WebGL** 执行浏览器验收，保留 `p4-*.png`、`p4-*.json` 及 PR 的 `video.webm`；*软件 GPU 不能冒充实体手机 GPU*。
